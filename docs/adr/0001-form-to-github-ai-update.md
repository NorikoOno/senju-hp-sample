# ADR-0001: Google フォームから AI 経由で HP を更新する仕組み

- 状態: 承認 (2026-11-10)
- 決定者: サイト運営者
- 関連: [README](../../README.md)

## 背景

えどぼり書道教室の HP は GitHub Pages で公開している静的サイト。
日常的に書き換えるのは次の 3 つだけで、いずれも専用のデータファイルに分離済み。

| 更新内容 | ファイル | 写真 |
|---|---|---|
| お知らせ | `news.js` | - |
| 開講日カレンダー | `calendar.js` | - |
| 生徒の作品の掲載・削除 | `works.js` | `works/` |

運営者は PC を開かず、スマホから「12月の子どもは 4,11,18,25」「この写真は小4金賞」のように
日本語で指示するだけで更新したい。GitHub の操作や JS の編集は AI に任せる。

当初は LINE を入口にする案 (LINE Messaging API + Cloudflare Worker) を検討したが、
LINE Developers と Cloudflare の 2 つのアカウント準備が必要になる。
運営者が Google アカウントを持っていれば Google フォーム + GAS だけで済むため、こちらを採用する。

## 決定

```
 スマホ (ブラウザ)          Google                            GitHub                          GitHub Pages
 ───────────────        ──────────────────────────      ─────────────────────────────       ────────────
 フォームに入力 ──送信──▶ 回答がスプレッドシートに記録
   ・やりたいこと          写真は Drive フォルダに保存
   ・指示の文章                 │
   ・写真 (任意)                ▼ onFormSubmit トリガー
                          GAS
                          送信者メールを許可リストと照合
                          写真を inbox/ にコミット ───────▶ GitHub Contents API
                          repository_dispatch を送信 ───▶ GitHub Actions
                                                           Claude Code が指示を読み
                                                           news.js / calendar.js / works.js /
                                                           works/ だけを編集 → 検証 → main に commit ──▶ 1〜2分で公開
                                                             │
 結果をメールで受け取る ◀── GAS (GmailApp) ◀── 完了通知 ──────┘
```

### D1. 入口は Google フォーム、橋渡しは GAS

フォームの項目は 3 つだけにする。

| 項目 | 形式 |
|---|---|
| やりたいこと | 選択式: お知らせ / 開講日カレンダー / 生徒の作品を追加 / 生徒の作品を削除 / 直前の更新を取り消す |
| 指示 | 自由記述 (例:「12月の子どもは 4,11,18,25。一般は 7,21」) |
| 写真 | ファイルアップロード (複数可、画像のみ)。作品の追加のときだけ使う |

- 回答はスプレッドシートに記録され、写真は Drive の専用フォルダに保存される (Google フォームの標準動作)。
- フォーム送信をトリガーに GAS が動き、写真を GitHub の `inbox/` にコミットし、`repository_dispatch` で Actions を起動する。
- GAS は「送信者の照合」「写真の転送」「Actions の起動」「結果メールの送信」だけを担当し、AI は置かない。

理由: 必要なのは Google アカウントだけ。フォームはスマホのブラウザで開け、ホーム画面に追加すればアプリのように使える。
写真アップロード付きフォームは Google ログインが必須なので、送信者のメールアドレスが確実に取れ、許可リストの照合に使える。

検討した代替

- LINE Messaging API + Cloudflare Worker: 会話形式で使えるが、アカウントが 2 つ増える。見送り。
- LINE + GAS: Cloudflare は不要になるが、GAS では LINE の署名検証ができない。見送り。

### D2. AI は GitHub Actions 上の Claude Code で動かす

- GAS は `repository_dispatch` (イベント `form-update`) に、やりたいこと・指示文・送信者・回答 ID を載せて送るだけ。
- Actions のジョブで Claude Code (`anthropics/claude-code-action` または `claude -p`) を起動し、
  指示文と `inbox/` の写真を渡して編集させる。
- 作業ログは Actions の実行履歴として残る。

理由: 編集対象がリポジトリそのものなので git の上で動かすのが自然。
何をどう変えたかが commit と Actions ログで追える。GAS 内で独自のエージェントループを書くより保守が楽。
公開リポジトリなので Actions の実行時間は無料。

### D3. 写真は `inbox/` を経由する (状態を持たない)

- GAS が Drive 上の写真を取り出し、GitHub Contents API で `inbox/<回答ID>-<連番>.jpg` にコミットする。
- AI は「`inbox/` にある写真 = 今回の指示の対象」として扱い、`works/<展覧会スラッグ>/` に移動し、`works.js` に追記し、`inbox/` を空にする。
- Actions 側で写真をリサイズ (長辺 1600px) し、EXIF (位置情報など) を削除してから配置する。
- Drive 側の写真は GAS が転送後に削除する (Drive 容量を使わず、リポジトリだけが唯一の保管場所になる)。

理由: GAS 側に状態を持たせずに済み、写真と指示の対応が回答 ID で一意に決まる。

### D4. 直接 main にコミットし、フォームの「取り消し」で戻す

- 承認ステップは置かず、AI の編集結果をそのまま main にコミットして公開する。
- 完了後、変更内容の要約と公開 URL を送信者にメールで返す。
- フォームで「直前の更新を取り消す」を選んで送ると、直前の bot コミットを `git revert` して公開し直す。

理由: 更新内容は低リスクで、間違えてもすぐ直せる。承認フローは仕組みが一段複雑になる。
運用してみて誤更新が多ければ「プレビュー → OK で公開」に切り替える (その場合は ADR を追加する)。

### D5. 結果通知は Actions → GAS → メール

- Actions は完了時 (成功・失敗とも) に GAS のウェブアプリ URL へ結果を POST する。共有の秘密トークンを本文に含め、GAS 側で照合する。
- GAS が `GmailApp` で送信者にメールを送る。件名に成功/失敗、本文に変更の要約と公開 URL、失敗時はエラー内容。

理由: Actions から直接メールを送るには SMTP の認証情報が要る。GAS に送らせれば追加の認証情報が不要で、送信元も運営者の Gmail になる。

### D6. ガードレール

AI に自由に書かせるが、守らせる範囲は仕組み側で強制する。

| 項目 | 方法 |
|---|---|
| 送信者の制限 | GAS が回答のメールアドレスを許可リスト (スクリプトプロパティ) と照合。それ以外は何もせず記録だけ残す |
| 編集できるファイル | Actions で `git diff --name-only` を検査。`news.js` `calendar.js` `works.js` `works/**` `inbox/**` 以外に差分があれば commit せず失敗させる |
| データの壊れ防止 | commit 前に `node --check` と読み込みテストで配列・オブジェクトとして読めることを確認 |
| 生徒のプライバシー | AI への指示書で、キャプションに生徒のフルネームを書かないこと、顔が写る写真はそのまま載せないことを明記。該当しそうな場合は変更せず、確認を求めるメールを返す |
| 失敗時 | エラー内容をメールで返す。サイトは直前の状態のまま |
| 秘密情報 | GitHub トークンと通知用トークンは GAS のスクリプトプロパティに、Anthropic API キーと通知用トークンは Actions secrets に置く。リポジトリには入れない |

## 使い方のイメージ

| フォームで送るもの | 起きること |
|---|---|
| お知らせ /「12/23(火)はお休みです」 | `news.js` の先頭に追加 |
| 開講日カレンダー /「12月の子どもは 4,11,18,25。一般は 7,21。31日は休講」 | `calendar.js` の 2026-12 を書き換え |
| 生徒の作品を追加 / 写真 3 枚 +「第40回 大阪書道展に出展。左から小4金賞、小6銀賞、中2特選」 | `works/2026-12-osaka-shodoten/` に配置、`works.js` に追記 |
| 生徒の作品を削除 /「大阪書道展の小6銀賞を消して」 | `works.js` から該当項目と写真を削除 |
| 直前の更新を取り消す | 直前の更新を revert |

## テストから本番への切り替え

1. フォーム・スプレッドシート・GAS は運営者 (このリポジトリの所有者) の Google ドライブに作る。
2. まず運営者自身のメールアドレスだけを許可リストに入れてテストする。
3. 動作確認できたら、実際の作業者のメールアドレスを許可リストに追加し、フォームの URL を共有する。
4. 必要なら作業者をフォームとスプレッドシートの共同編集者に追加する。

切り替えで変わるのは許可リストの値だけで、フォーム・GAS・Actions のコードは変わらない。

## 結果 (Consequences)

良い点

- 作業者はフォームに書いて送るだけ。GitHub や JS を触らない。
- 変更履歴がすべて git に残り、いつでも戻せる。
- 必要なアカウントは Google と Anthropic だけ。追加のサーバーやデータベースはない。
- 回答がスプレッドシートに残るので、「いつ誰が何を頼んだか」の台帳にもなる。

注意点

- 反映まで 1〜3 分かかる (Actions 起動 + Pages ビルド)。即時ではない。
- 会話形式ではないので「今のお知らせ見せて」のような問い合わせはできない。代わりに結果メールに現在の内容へのリンクを含める。
- 写真アップロードには作業者の Google ログインが必要。
- Anthropic API の費用が 1 更新あたり数円〜十数円かかる。
- GAS の制限 (1 実行 6 分、外部通信 1 日 2 万回、メール 1 日 100 通) はこの用途では十分。

## 構築の順序

1. Anthropic API キーを用意する (運営者)
2. Google フォームとスプレッドシートを作り、GAS を紐づける
3. GitHub の fine-grained トークン (このリポジトリの contents 書き込みのみ) を発行し、GAS のスクリプトプロパティに設定する
4. `.github/workflows/form-update.yml` と AI への指示書 `docs/ai-editor-guide.md` を追加する
5. GAS をウェブアプリとして公開し、その URL と通知用トークンを Actions secrets に設定する
6. 運営者自身のアカウントで、お知らせ → カレンダー → 作品の追加 → 作品の削除 → 取り消し の順に動作確認する
7. 作業者のメールアドレスを許可リストに追加し、フォーム URL を共有する
