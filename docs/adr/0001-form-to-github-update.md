# ADR-0001: Google フォームから HP を更新する仕組み (AI なし)

- 状態: 承認 (2026-11-10)
- 決定者: サイト運営者
- 関連: [README](../../README.md)、[GAS 設定手順](../../tools/gas/README.md)

## 背景

えどぼり書道教室の HP は GitHub Pages で公開している静的サイト。
日常的に書き換えるのは次の 3 つだけで、いずれも専用のデータファイルに分離済み。

| 更新内容 | ファイル | 写真 |
|---|---|---|
| お知らせ | `news.js` | - |
| 開講日カレンダー | `calendar.js` | - |
| 生徒の作品の掲載・削除 | `works.js` | `works/` |

運営者は PC を開かず、スマホから更新したい。GitHub の操作や JS の編集はさせない。

### 経緯

1. 当初は「LINE で自由文を送り、AI が解釈して編集する」案 (LINE Messaging API + Cloudflare Worker + Claude Code) を検討した。
2. アカウント準備を減らすため、入口を Google フォーム + GAS に変更した。
3. AI の利用料 (1 回数円〜十数円) を避けたいという要望があり、無料 AI (GitHub Models、Gemini 無料枠) も検討したが、
   更新内容が 3 種類に限られているため **AI を使わず、フォームの項目を構造化して確定的に書き換える** 方式に決めた。

## 決定

```
 スマホ (ブラウザ)             Google                                GitHub                              GitHub Pages
 ─────────────────         ─────────────────────────────         ────────────────────────────────         ────────────
 フォームで項目を選んで送信 ──▶ GAS (onFormSubmit)
   ・やりたいこと               送信者メールを許可リストと照合
   ・各項目の入力欄             写真を inbox/ にコミット ────────────▶ Contents API
   ・写真 (作品追加のみ)         repository_dispatch(form-update) ──▶ Actions: form-update.yml
                                                                     tools/prepare-photos.sh  写真を縮小・EXIF 削除
                                                                     tools/apply-update.js    JS ファイルを書き換え
                                                                     tools/validate.js        壊れていないか検査
                                                                     commit → push ──────────────────────▶ 1〜2分で公開
                                                                       │
 結果メール ◀── GAS (doPost → GmailApp) ◀── 完了通知 ─────────────────┘
                 ついでに「消すお知らせ」「消す作品」の選択肢を更新
```

### D1. AI は使わない。フォームの項目を構造化する

「やりたいこと」を選ぶと、それ専用の入力欄だけが出る (Google フォームのセクション分岐)。

| やりたいこと | 入力欄 |
|---|---|
| お知らせを追加 | 本文、日付 (空欄なら今日) |
| お知らせを削除 | 既存のお知らせをプルダウンから選ぶ |
| 開講日カレンダー | 対象の月 (プルダウン)、幼年・小学生・中学生 (木曜) の日にち、高校生・大学生・一般 (日曜) の日にち、休講日、ひとこと |
| 生徒の作品を追加 | 展覧会名、展覧会の一言、写真 (複数)、写真ごとの一言 (1 行 1 枚、送った順) |
| 生徒の作品を削除 | 既存の作品、または展覧会ごと、をプルダウンから選ぶ |
| 直前の更新を取り消す | 入力なし |

理由: 自由文を AI に解釈させる必要がない。読み違いが起きず、費用がかからない。
削除対象をプルダウンにすることで、名前の打ち間違いもなくなる。選択肢は更新のたびに GAS がサイトのデータから作り直す。

日にちは「4,11,18,25」のように数字を区切って書く。全角数字や「、」「日」が混ざっても読み取る。

### D2. 書き換えロジックはリポジトリ内の Node スクリプトに置き、GitHub Actions で動かす

- GAS は `repository_dispatch` に「やりたいこと」と入力値をそのまま載せて送るだけ。
- Actions 上で `tools/apply-update.js` がデータファイルを読み、書き換え、`tools/validate.js` が検査し、main に commit する。
- 写真の縮小 (長辺 1600px)、EXIF 削除、HEIC → JPG 変換は `tools/prepare-photos.sh` が ImageMagick で行う。

理由: GAS は画像処理ができず、コードのテストもしにくい。ロジックをリポジトリ側に置けば手元で実行して確認でき、
変更履歴も残る。GAS は「許可リスト、写真の転送、起動、メール、選択肢更新」だけの薄い層になる。
公開リポジトリなので Actions の実行時間は無料。

### D3. 写真は `inbox/` を経由する (状態を持たない)

- GAS が Drive 上の写真を取り出し、`inbox/<回答ID>-<連番>.<拡張子>` にコミットしてから Actions を起動する。
- `apply-update.js` は自分の回答 ID で始まる写真だけを `works/<回答ID>/01.jpg, 02.jpg, …` に移し、`works.js` に追記する。
  それ以外に `inbox/` に残っている写真は過去の失敗の残骸とみなして削除する。
- Drive 側の写真は転送後にゴミ箱へ入れる。リポジトリだけが唯一の保管場所。

理由: GAS 側に保存先や状態を持たせずに済む。作品フォルダ名に回答 ID (日時) を使うので、展覧会名のローマ字化が不要。

### D4. 直接 main にコミットし、フォームの「取り消し」で戻す

- 承認ステップは置かず、検査を通った変更はそのまま main にコミットして公開する。
- 完了後、変更内容の要約と公開 URL を送信者にメールで返す。
- 「直前の更新を取り消す」を送ると、直前の `form-update:` コミットを `git revert` して公開し直す。続けて送れば 1 つ前、さらに前と戻せる。

理由: 更新内容は低リスクで、間違えてもすぐ直せる。承認フローは仕組みが一段複雑になる。

### D5. 結果通知は Actions → GAS → メール

- Actions は完了時 (成功・失敗・変更なし) に GAS のウェブアプリ URL へ結果を POST する。合言葉 (`NOTIFY_TOKEN`) を本文に含め、GAS が照合する。
- GAS が `GmailApp` で送信者にメールを送り、同時にプルダウンの選択肢を更新する。

理由: Actions から直接メールを送るには SMTP の認証情報が要る。GAS に送らせれば追加の認証情報が不要で、送信元も運営者の Gmail になる。

### D6. ガードレール

| 項目 | 方法 |
|---|---|
| 送信者の制限 | 写真付きフォームは Google ログイン必須。GAS が回答のメールアドレスを許可リスト (スクリプトプロパティ `ALLOWED_EMAILS`) と照合し、それ以外は無視する |
| 編集できるファイル | `validate.js` が `git status` を検査。`news.js` `calendar.js` `works.js` `works/**` `inbox/**` 以外に差分があれば commit せず失敗させる |
| データの壊れ防止 | commit 前にデータファイルを読み込み、配列・オブジェクトの形、日付の範囲、写真の存在、ファイルサイズ (5MB 以下) を検査 |
| 失敗時 | 原因をメールで返す。サイトは直前の状態のまま |
| 生徒のプライバシー | 一言にはフルネームを書かない、顔が写る写真は載せない、という運用ルールをフォームの説明文に明記する (仕組みでは判定しない) |
| 秘密情報 | GitHub トークンと合言葉は GAS のスクリプトプロパティに、合言葉と GAS の URL は Actions secrets に置く。リポジトリには入れない |

## テストから本番への切り替え

1. フォームと GAS は運営者 (このリポジトリの所有者) の Google アカウントに作る。
2. まず運営者自身のメールアドレスだけを `ALLOWED_EMAILS` に入れてテストする。
3. 動作確認できたら、作業者のメールアドレスを `ALLOWED_EMAILS` に追加し、回答用 URL を共有する。
4. 必要なら作業者をフォームの共同編集者に追加する。

切り替えで変わるのは `ALLOWED_EMAILS` の値だけ。

## 結果 (Consequences)

良い点

- 完全無料。費用がかかる部品がない (Google、GitHub Actions、GitHub Pages はいずれも無料枠内)。
- 動作が決定的で、同じ入力なら必ず同じ結果になる。読み違いがない。
- 変更履歴がすべて git に残り、いつでも戻せる。
- フォームの回答がスプレッドシートにも残り、「いつ誰が何を頼んだか」の台帳になる。
- 書き換えロジックは `node tools/apply-update.js` で手元でもテストできる。

注意点

- 自由文では頼めない。項目にない更新 (例: 月謝の変更) は従来どおりファイルを直接編集する。
- 反映まで 1〜3 分かかる (Actions 起動 + Pages ビルド)。
- 写真アップロードには作業者の Google ログインが必要。
- フォームの「写真」の質問だけはスクリプトで作れないため、初回に手で追加する。
- GitHub の fine-grained トークンには有効期限がある。切れたら作り直してスクリプトプロパティを更新する。
